Issue-by-issue handling

#21: model.py IndexError in test phase

code fixed

Root cause: FPS was sometimes asked to sample more points than available candidates. The custom CUDA op can then return invalid indices, which crash NumPy indexing during patch extraction or final output sampling.

Fix:

  • Added Upsampling/sampling_utils.py with clamp_sample_count() and safe_index_array().
  • Clamped patch seed count before farthest_point_sample().
  • Filtered/fixed FPS indices before indexing pc and pred_pc.
  • Warns if requested output points exceed candidate predictions.

#10: Metric calculation and PU-GAN dataset

Hausdorff code fixed P2F/dataset documented

Root cause: Hausdorff used the sum of directional maxima. Symmetric Hausdorff should be max(max(A), max(B)).

Fix: Added Common/metrics.py::hausdorff_from_nn_distances() and updated evaluate.py.

P2F note: I did not silently change P2F to a symmetric metric because that would break comparability with existing PU-GCN/PU-GAN/MPU tables. I documented that current P2F is prediction-to-mesh-surface only.

#11: P2F metric returns NaN

robustness fixed

Root cause: NaNs can come from non-finite prediction points, unreadable/empty input files, invalid mesh input, or unstable CGAL closest-surface projection.

Fix: evaluation_code/evaluation.cpp now checks file opening, validates prediction extensions, filters non-finite points, skips non-finite projections/distances, and avoids NaN std for a single valid distance.

#13: Evaluation compilation fails, then no ./evaluation

build script fixed

Root cause: CMake only printed a warning when CGAL was missing, so no executable was built, but compile.sh still ran ./evaluation.

Fix: CMake now uses FATAL_ERROR when CGAL is missing; compile.sh uses set -euo pipefail, documents apt/module dependency hints, and checks executable existence before running.

#16: Empty HDF5 file in PU1K/train

support script added

Root cause: Most likely incomplete Google Drive download, failed unzip, or zero-byte placeholder. The released ZIP contains a non-empty HDF5 file.

Fix: Added tools/check_h5.py to report file size, keys, shapes, and optional finite-coordinate checks.

python tools/check_h5.py ./data/PU1K/train/pu1k_poisson_256_poisson_1024_pc_2500_patch50_addpugan.h5 --check_finite

#18: Custom Dataset

converter added

Request: How to convert custom meshes to PU-GCN HDF5 format.

Fix: Added tools/mesh_to_h5.py, which samples mesh surfaces and writes poisson_1024 and poisson_256 keys.

pip install trimesh h5py scipy
python tools/mesh_to_h5.py --mesh_glob "./my_meshes/*.off" --output ./data/custom.h5 --samples_per_mesh 20

#17: PU1K filename contains addpugan

documented

Fix: Added a FAQ note in docs/issue_fixes.md: the addpugan suffix indicates PU-GAN-style additional training data/patches for baseline compatibility; it is not a corrupted download.

#15: Where is PU-GAN test data?

documented

Fix: Added a FAQ note explaining that PU-GAN's public test release is mesh-based. Point-cloud input/GT pairs are typically generated from meshes by each evaluation pipeline; PU1K includes explicit point-cloud test files and is better for reproducible point-cloud pairs.

#14: KITTI raw has hollow upsampled clouds

documented mitigation

Root cause: Domain mismatch: PU-GCN checkpoints are trained on normalized object/patch datasets, not full raw sparse LiDAR scenes.

Fix: Added mitigation guidance: use matching random/uniform checkpoint, crop/normalize local patches, increase patch overlap, and treat KITTI raw as domain-transfer rather than benchmark reproduction.
